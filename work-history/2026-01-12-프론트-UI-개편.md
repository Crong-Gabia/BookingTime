# 프론트 UI 개편

## 개요

- **작업 기간**: 2026-01-12
- **작업자**: Sisyphus
- **목표**: 프론트 UI를 개편하여 재사용 가능한 컴포넌트 기반으로 만들고, 지침 문서를 작성하여 화면을 예쁘게 구성하고 기능을 빠르게 확인할 수 있도록 만들기

---

## 수행한 작업

### 컴포넌트 설계 목록화
- StatusChip (상태 칩): 응답 상태, 시간 슬롯 상태 표시
- MeetingCard (일정 카드): 대시보드에서 일정 요약 정보 표시
- ParticipantList (참석자 리스트): 참석자 목록과 재요청 버튼
- TimeSlot (시간 슬롯): 30분 단위 시간 선택
- TimeGrid (시간 그리드): 날짜별 시간 슬롯 그리드
- ProgressBar (진행률 바): 응답률 표시
- SectionHeader (섹션 헤더): 카드/섹션 제목
- StickyActionBar (고정 하단 액션바): 모바일 응답 페이지 하단 버튼
- EmptyState (빈 상태): 데이터 없음 표시
- LoadingState (로딩 상태): 로딩 중 표시
- RoomSelector (회의실 선택): 회의실 드롭다운
- CommonSlots (공통 가능 시간 리스트): 공통 가능 시간 표시
- FloatingButton (플로팅 버튼): 새 일정 만들기
- ConfirmDialog (확인 다이얼로그): 최종 확정 전 확인

### 페이지별 레이아웃 개편 계획 수립
- **Home (Dashboard)**: 진행 중/완료된 조율 목록 + MeetingCard + FloatingButton
- **일정 생성 (Create)**: 기본 정보/참석자 선택/시간 기간 설정 + 단열 레이아웃
- **응답 페이지 (Response)**: TimeGrid + StickyActionBar (모바일 최적화)
- **주좩자 상세/확정 (Detail & Confirm)**: ParticipantList + CommonSlots + RoomSelector + 좌우 분할 레이아웃

### 지침 문서 작성
- `guidelines/01-ui-components.md`: 14개 컴포넌트의 Props, 위치, 사용 예시
- `guidelines/02-layout-patterns.md`: 4개 페이지의 레이아웃 구조, MUI Grid 사용, 반응형 패턴
- `guidelines/03-status-colors.md`: 응답/시간 슬롯/일정 상태별 색상 정의, MUI 테마 설정
- `guidelines/04-data-fetching.md`: TanStack Query 사용법, API 래퍼 구조, 캐시 전략, 에러 처리
- `guidelines/05-types.md`: TypeScript 타입 정의 규칙, 주요 타입(일정/참석자/시간 슬롯/회의실/API 응답)
- `guidelines/06-testing.md`: Vitest + React Testing Library 설정, 컴포넌트/훅/API 래퍼 테스트 예시

### 작업 기록 템플릿 정리

## 의사결정 사항

- **지침 폴더 위치**: `guidelines/`로 결정 (단일 폴더에 모든 지침 모음)
- **작업 기록 위치**: `work-history/` 유지 (기존 패턴과 동일)
- **MUI 사용**: 기존 설치된 MUI(@mui/material)를 기반으로 컴포넌트 작성, 인라인 스타일 대체
- **TanStack Query**: 모든 데이터 패칭에 TanStack Query 사용 (useQuery: GET, useMutation: POST/PUT/DELETE)
- **API 래퍼**: `apps/web/src/api/` 디렉토리에 모듈화 (health.ts, meeting.ts 등)
- **타입 정의**: 공유 타입은 `@shared/dto`에서 import, 프론트 전용 타입은 `apps/web/src/types/`에 정의
- **반응형**: 모바일 우선(Mobile First), 데스크톱에서 `Grid` 또는 `Box`의 `sx` prop에서 브레이크포인트 사용
- **Phase 범위**: Phase 1 MVP 기능 기준으로 개편 (기획서 참조), Phase 2(SSO 외부 데이터 연동, AI 추천 등)은 추후 계획

## 참고 사항

- 기획서 기반으로 Phase 1 MVP 범위(연차/휴가 필터링, 웹 링크 응답, 사내 메신저 알림, 대시보드, 회의실 예약) 구현
- Phase 2 로드맵(SSO 외부 데이터 연동, AI 추천, 자동 회의실 배정, 외부 캘린더 연동)은 추후 계획
- 모든 시간은 데이터베이스에 UTC로 저장, UI는 Asia/Seoul(KST)로 표시
- 30분 단위 슬롯 (09:00-18:00, 점심시간 12:00-13:00 제외, 주말 제외)
- Negative Selection: 기본적으로 모든 업무 시간을 "가능(Available)"으로 간주하고, 참석자가 "안 되는 시간(Unavailable)"만 선택
