# 2026-01-13

## TL;DR
- 프론트엔드에서 `requestJson` 기반 **API 래퍼 구조**를 잡고, 주요 페이지를 새 래퍼로 교체.
- `gh`(GitHub CLI) 설치/로그인 문서를 보강했고, OpenCode/Oh My Open Code 설치 및 SSL 이슈 대응을 기록.
- 가장 큰 블로커는 **API 서버 미구동 + @shared/dto/Prisma 타입 이슈**로 정리됨(우선순위 1).

## Status
- **Signal**: Yellow
- **Summary**: 문서/프론트 구조는 진전됐지만, API 서버 정상화가 지연되어 "실제 플로우 검증"이 막혀 있음.

## Decisions
- **Decision**: API 호출을 `requestJson` 헬퍼로 통일
  - Why: 에러 메시지 추출/응답 파싱을 한 곳에서 처리해 호출부를 단순화.
  - Impact: 페이지/훅은 TanStack Query 패턴을 유지하면서 타입 안전하게 교체 가능.
  - Link: ../2026-01-13-api-wrapper.md
- **Decision**: 페이지 UI 제어는 로컬 state 대신 `useMutation` 상태(`isPending`) 중심
  - Why: 로딩/에러 상태를 TanStack Query 표준 패턴으로 통일.
  - Impact: 사용자 피드백(loading/disabled) 일관성 향상.
  - Link: ../2026-01-13-api-wrapper.md
- **Decision**: OpenCode 설치는 npm 글로벌 대신 공식 설치 스크립트 사용
  - Why: `npm install -g opencode` E404 회피.
  - Impact: 설치/업그레이드 경로가 공식 문서 기준으로 정리.
  - Link: ../2026-01-13-oh-my-open-code-setup.md

## Risks
- **Risk**: API 서버가 실행되지 않아 프론트 변경이 실제 API와 맞물려 검증되지 않음
  - Severity: High
  - Mitigation: `pnpm --filter api dev` + `GET /api/health`부터 정상화(빌드/런타임 이슈 분리).
  - Link: ../2026-01-13-current-work.md
- **Risk**: `NODE_TLS_REJECT_UNAUTHORIZED=0`는 보안적으로 위험(임시 우회)
  - Severity: High
  - Mitigation: 회사 CA를 `NODE_EXTRA_CA_CERTS`로 설정하는 영구 해결을 기본으로 문서화.
  - Link: ../2026-01-13-oh-my-open-code-setup.md
- **Risk**: @shared/dto ↔ Prisma enum/export 불일치로 타입/빌드가 반복적으로 깨질 가능성
  - Severity: Medium
  - Mitigation: 서버 측에서 Prisma 타입 사용 전략을 확정하거나, 공유 DTO 레이어에 명시적 타입/enum 정의로 안정화.
  - Link: ../2026-01-13-current-status.md

## Next

2. Prisma enum/export 이슈(MeetingStatus/SlotStatus 등) 처리 전략을 확정하고 코드/DTO를 일관화.
