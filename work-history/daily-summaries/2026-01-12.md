# 2026-01-12

## TL;DR
- SSO/인증 요구사항을 제거하고, **이메일 입력 + 링크 공유** 중심으로 MVP 범위를 확정.
- 프론트엔드에서 **Create/Dashboard/Response 흐름**을 기획서 기준으로 구현하고 라우팅을 정리.
- 실행/배포/페이지 구조 문서를 추가해 "어떻게 띄우고/어디를 구현했는지"를 빠르게 따라가게 함.

## Status
- **Signal**: Yellow
- **Summary**: 프론트 주요 플로우는 구성됐지만, 백엔드(LSP/빌드) 이슈와 테스트/검증이 남아 있음.

## Decisions
- **Decision**: SSO/인증 제거(링크 기반 공유로 전환)
  - Why: MVP에서 사용자/권한 흐름 복잡도를 줄이고 "조율" 핵심 플로우에 집중.
  - Impact: 참가자는 링크로 응답, 주최자는 대시보드 링크로 상태 확인.
  - Link: ../2026-01-12-initial-setup.md
- **Decision**: HR/Holiday/Room 어댑터는 Fake 구현체 유지
  - Why: 외부 연동은 Phase 2로 미루고 기능 흐름 검증 우선.
  - Impact: 기능 데모/개발 속도는 확보되지만, 실제 운영 적합성 검증은 보류.
  - Link: ../2026-01-12-initial-setup.md
- **Decision**: PostgreSQL + Docker Compose 유지
  - Why: 로컬 재현성과 팀 온보딩 비용 최소화.
  - Impact: 개발/테스트 환경 표준화.
  - Link: ../2026-01-12-execution-guide.md

## Risks
- **Risk**: 백엔드 LSP/컴파일 오류로 API 서버가 정상 구동되지 않을 수 있음
  - Severity: High
  - Mitigation: NestJS 데코레이터/tsconfig 설정 및 타입 import 이슈를 먼저 정리.
  - Link: ../2026-01-12-initial-setup.md
- **Risk**: 테스트/통합 검증 부재로 "흐름이 실제로 동작"하는지 확신이 낮음
  - Severity: Medium
  - Mitigation: 핵심 로직 단위 테스트 + end-to-end 시나리오(생성→응답→확정) 검증.
  - Link: ../2026-01-12-execution-guide.md
- **Risk**: Home의 리스트 UI가 placeholder 기반이라 실제 데이터 연동 시 UX/스키마 불일치 가능
  - Severity: Medium
  - Mitigation: 회의 목록 API/DTO를 먼저 확정하고 UI를 그에 맞춰 연결.
  - Link: ../2026-01-12-web-page-structure.md
