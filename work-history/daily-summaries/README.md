# Daily Summaries (하루 요약)

작업 문서(`work-history/YYYY-MM-DD-*.md`)가 많아질수록 "오늘 뭐가 바뀌었고, 다음에 뭘 해야 하는지"를 찾기 어려워집니다.
이 디렉토리는 **사람이 3분 안에 상황 파악**할 수 있도록, 하루 단위로 요약을 모읍니다.

## Index

- `2026-01-12`: [2026-01-12.md](./2026-01-12.md)
- `2026-01-13`: [2026-01-13.md](./2026-01-13.md)

## 규칙 (중요)

### 1) 파일 규칙
- 파일은 하루 1개: `work-history/daily-summaries/YYYY-MM-DD.md`
- 제목은 날짜로 시작: `# YYYY-MM-DD` (검색/정렬/스캔 최적화)

### 2) 요약의 역할
- 요약은 **원문을 복붙해서 늘리는 문서가 아님**
- 요약은 **결론/결정/리스크/다음 액션** 중심 + 상세는 링크로 이동

### 3) 길이 제한
- 목표: **1~2페이지** (대략 50~120줄 / 400~900 단어 수준)
- 초과하면 "무엇이 중요했나"가 묻히므로 반드시 줄입니다.

### 4) 필수 섹션 (고정)
아래 섹션은 반드시 포함합니다.

- `## TL;DR` (3~6 bullet)
- `## Status` (Green/Yellow/Red + 한 줄 요약)
- `## Decisions` (결정 + 이유 + 영향 + 링크)
- `## Risks` (리스크 + 심각도 + 대응 + 링크)
- `## Next` (3~7개의 구체 액션)
- `## Links` (원문/PR/이슈/참조 링크)

### 5) 링크 규칙
- **반드시 원문으로 역링크**합니다.
  - 같은 날짜의 상세 작업: `../YYYY-MM-DD-*.md`
  - 제품 스펙/결정/리스크: `../product-spec/*.md`
  - 지속 가이드라인: `../../guidelines/`, `../../docs/`
- 링크는 "그냥 나열"이 아니라, 섹션별로 그룹핑합니다.

## Success Criteria (이 레이어가 "성공"인 기준)

| 종류 | 기준 | Pass/Fail |
|---|---|---|
| Functional | 하루당 요약 파일 1개가 존재 | 날짜당 파일 1개면 Pass |
| Functional | 필수 섹션 6개가 모두 포함 | 누락 시 Fail |
| Observable | 요약만 읽어도 오늘의 핵심 변화/결정/리스크/다음 액션이 3분 내 파악 | 불가능하면 Fail |
| Observable | `Links`에서 원문(상세 문서)로 즉시 이동 가능 | 링크가 깨지면 Fail |
| Quality | 원문 복붙 없이 요약/결론 중심 | 과도한 복붙이면 Fail |

## Test Plan

### Objective
- daily summary 레이어가 "읽기 쉬운 내비게이션"으로 동작하는지 검증

### Test Cases
1. **Structure**: 각 `YYYY-MM-DD.md`에 필수 섹션 6개가 존재 → 텍스트로 확인
2. **Link Hygiene**: `Links`의 repo-local 링크가 상대경로로 올바름 → 파일 경로를 따라가며 확인
3. **One-per-day**: 날짜별 요약 파일이 중복되지 않음 → `ls`로 확인
4. **Brevity**: 길이가 1~2페이지 수준 유지 → 줄 수/단락 수로 확인

### How to Execute
- `ls work-history/daily-summaries`
- 각 요약 파일을 열어 섹션/링크를 점검

## 템플릿
- 새 요약 작성은 [TEMPLATE.md](./TEMPLATE.md)를 복사해서 시작합니다.
