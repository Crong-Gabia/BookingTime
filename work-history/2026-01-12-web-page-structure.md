# 웹 페이지 구조 트리

## 현재 구현된 페이지

### apps/web/src/pages/
```
apps/web/src/pages/
├── HomePage.tsx              # 홈 화면 (현재: Health 체크만)
├── DashboardPage.tsx         # 주최자 대시보드 (현재: 기본 구조)
└── ResponsePage.tsx          # 참석자 응답 페이지 (현재: 하루 기준 슬롯)
```

## 라우팅 (App.tsx)
```tsx
<Routes>
  <Route path="/" element={<HomePage />} />
  <Route path="/requests/:id/dashboard" element={<DashboardPage />} />
  <Route path="/requests/:id/respond" element={<ResponsePage />} />
</Routes>
```

## 기획서 기준 페이지 구조

### 1. Home (대시보드)
**현재 상태**: Health 체크만 있음

**필요 기능**:
- [ ] 진행 중인 조율 목록
- [ ] 카드 형태 일정 요약 (제목, 기간, 응답률)
- [ ] 상세 보기 / 확정하기 버튼
- [ ] 완료된 조율 목록 (히스토리)
- [ ] + 새 일정 만들기 플로팅 버튼

**추가해야 할 페이지**:
- `/requests/new` - 회의 요청 생성 페이지

### 2. 일정 생성 (Create)
**현재 상태**: 없음

**필요 기능**:
- [ ] 기본 정보 입력 (제목, 설명)
- [ ] 참석자 선택 (이메일 입력, SSO 제거 후)
- [ ] 시간/기간 설정 (소요시간, 날짜 범위, 시간대 필터)

### 3. 응답 페이지 (Response - Mobile/PC)
**현재 상태**: 기본 UI 있음 (하루 기준 슬롯)

**필요 기능**:
- [ ] 일정 개요 (제목, 주최자, 소요시간)
- [ ] Time Grid (날짜별 세로 스크롤)
- [ ] [Toggle] 전체 가능 / 전체 불가 버튼
- [ ] [Slot] 시간대별 상태 (가능/불가/Blocked)
- [ ] 제출 완료 페이지

**개선 필요**:
- [ ] 날짜별 슬롯으로 변경 (현재: 하루만)

### 4. 주최자 상세/확정 (Detail & Confirm)
**현재 상태**: DashboardPage의 일부 구현됨

**필요 기능**:
- [ ] 응답 현황판 (참석자 리스트, 상태, 독촉 버튼)
- [ ] "모두 가능한 시간" 섹션
- [ ] 날짜별로 그룹핑하여 시간 리스트 노출
- [ ] 시간 클릭 시 예약 가능한 회의실 드롭다운 활성화
- [ ] 회의실 선택 후 최종 확정 버튼 활성화
- [ ] 최종 완료 페이지

## 전체 페이지 트리 (기획서 기준)

```
/                           (Home - 대시보드)
├── /requests/new            (일정 생성)
├── /requests/:id/dashboard   (주최자 상세/확정)
│   ├── 참가자 현황
│   ├── 공통 가능 시간
│   ├── 회의실 선택
│   └── 확정하기
└── /requests/:id/respond     (참가자 응답)
    ├── 일정 개요
    ├── Time Grid (날짜별)
    ├── Toggle 전체 가능/불가
    ├── Slot 선택
    └── 제출
```

## 개발 우선순위

1. **HomePage 개선** (1-2시간)
   - Health 체크 유지
   - 조율 목록/히스토리 추가
   - 새 일정 만들기 버튼 추가

2. **회의 요청 생성 페이지** (2-3시간)
   - `/requests/new` 페이지 새로 생성
   - 폼: 제목, 설명, 참석자 이메일, 기간, 소요시간

3. **DashboardPage 완성** (2-3시간)
   - URL 파라미터 처리 (:id)
   - 응답 현황판 구현
   - 공통 가능 시간 + 회의실 선택 + 확정 버튼

4. **ResponsePage 개선** (1-2시간)
   - 날짜별 슬롯 생성 (API 연동)
   - 전체 가능/불가 토글 추가
   - 제출 완료 페이지 구현

5. **공통 스타일/컴포넌트 정리** (1시간)
   - MUI 컴포넌트로 교체
   - 반응형 스타일 (모바일)
