# 작업 기록 템플릿

이 템플릿은 WhatTime 프로젝트의 작업 기록을 작성할 때 사용됩니다.

---

## 작업 기록 파일 생성 규칙

### 파일 이름 형식
```
work-history/YYYY-MM-DD-{작업-제목}.md
```

### 작업 제목 규칙
- kebab-case 사용 (예: `프론트-UI-개편`, `백엔드-API-추가`)
- 간결하고 명확한 제목 사용

---

## 작성 예시

```markdown
# 프론트 UI 개편

## 개요

- **작업 기간**: 2026-01-12
- **작업자**: Sisyphus
- **목표**: 프론트 UI를 개편하여 재사용 가능한 컴포넌트 기반으로 만들고, 지침 문서를 작성

---

## 수행한 작업

### 컴포넌트 설계
- StatusChip, MeetingCard, ParticipantList, TimeSlot, TimeGrid 등 14개 컴포넌트 설계
- 각 컴포넌트의 Props 인터페이스 정의

### 페이지 레이아웃 개편
- Home, Create, Response, Detail & Confirm 페이지 레이아웃 설계
- 모바일 우선, 반응형 레이아웃 패턴 정의

### 지침 문서 작성
- `guidelines/01-ui-components.md`: UI 컴포넌트 규칙
- `guidelines/02-layout-patterns.md`: 레이아웃 패턴
- `guidelines/03-status-colors.md`: 상태 색상 규칙
- `guidelines/04-data-fetching.md`: 데이터 패칭 규칙
- `guidelines/05-types.md`: 타입 정의 규칙
- `guidelines/06-testing.md`: 테스트 가이드라인

---

## 의사결정 사항

- **지침 폴더 위치**: `guidelines/`로 결정
- **작업 기록 위치**: `work-history/` 유지 (기존과 동일)
- **MUI 사용**: 기존 설치된 MUI를 기반으로 컴포넌트 작성
- **TanStack Query**: 모든 데이터 패칭에 TanStack Query 사용

---

## 발생한 이슈 및 해결 방법

### 없음
- 특별한 이슈 없음

---

## 다음 단계 계획

1. 재사용 컴포넌트 구현 (StatusChip, MeetingCard 등)
2. 페이지 레이아웃 리팩터링 (Home, Dashboard, Response)
3. API 래퍼 구현 (meeting.ts, health.ts 등)
4. 타입 정의 및 @shared/dto 연동
5. 테스트 파일 작성

---

## 토큰 사용량

- **총 토큰 사용량**: 12,345 토큰
- **세션 ID**: ses_example123
- **작업 시간**: 1시간 30분

---

## 참고 사항

- Phase 1 MVP 기능 기준으로 개편 (기획서 참조)
- Phase 2 로드맵(SSO 외부 데이터 연동, AI 추천 등)은 추후 계획
```
